# Tech Stack

## Backend

- **FastAPI** — the API framework. Chosen for auto-generated OpenAPI docs
  (`/docs`), native Pydantic validation, and async support.
- **Pydantic** — request/response schema validation (`backend/schemas.py`).
- **SQLAlchemy** — ORM over SQLite (`backend/database.py`,
  `backend/models.py`) for users, alert subscriptions, and sent-alert logs.
  SQLite specifically so the whole demo runs from one file with zero
  external database setup.
- **PyJWT** — JWT issuance/verification for auth (`backend/auth.py`).
  Password hashing uses stdlib `hashlib.pbkdf2_hmac` rather than an extra
  bcrypt/passlib dependency.
- **Twilio SDK** (optional) — real SMS delivery path in
  `backend/sms_provider.py`, only imported/used if Twilio credentials are
  set as environment variables; otherwise a stub path handles everything.

## Machine learning

- **XGBoost** — the core residual-delay model, plus the two quantile
  models (10th/90th percentile) that form the asymmetric confidence
  interval. Chosen over a linear model for its ability to capture
  nonlinear interactions (e.g. congestion mattering more during peak
  hours) without heavy feature engineering, and over a deep model for
  training speed and interpretability on tabular data.
- **scikit-learn** — `IsolationForest` for anomaly detection
  (`ml/anomaly.py`); also `train_test_split`, `mean_absolute_error`, and
  the `OneHotEncoder`/`ColumnTransformer`/`Pipeline` used by the
  historical model.
- **SHAP** — per-prediction feature attribution (`TreeExplainer`) for both
  the live model (`ml/predict.py`) and the historical model
  (`ml/predict_historical.py`). Chosen because it explains the *actual*
  fitted model's behavior on a *specific* prediction, rather than a
  global "these features matter on average" statement.
- **PyTorch** — the LSTM benchmark model (`ml/train_lstm.py`), trained
  over each train's full ordered station sequence rather than
  per-station summary features.
- **pandas / numpy** — feature engineering and data manipulation
  throughout `ml/`.
- **Faker** — synthetic station/route name generation in
  `data_simulator/simulate.py`.
- **joblib** — model serialization (`models/*.pkl`).

## Frontend

- **React 18** — the dashboard UI (`frontend/src/main.jsx`), function
  components + hooks only, no class components or external state library
  (the app's state is simple enough that `useState`/`useMemo` cover it).
- **Vite** — dev server and build tool. Chosen for fast HMR during
  development over the demo period.
- **Plain CSS** (`frontend/src/styles.css`) — no CSS framework. The
  design is a specific, intentional light-theme dashboard aesthetic,
  which a utility framework would fight against more than help with.

## Load testing

- **httpx** (async client) — `scripts/load_test.py` fires concurrent
  requests against a real running server and reports p50/p95/p99 latency
  and throughput.

## Data

- **Synthetic dataset** (`data/train_events.csv`) — generated by
  `data_simulator/simulate.py`; the source of truth for the live ETA
  model, anomaly model, and LSTM benchmark.
- **Real historical dataset** (`data/train_delay_data.csv`) — an uploaded
  CSV of real historical delay records, used only by the historical model
  pipeline (`ml/train_historical_model.py`,
  `backend/routers/historical.py`), kept deliberately separate from the
  synthetic data above.
