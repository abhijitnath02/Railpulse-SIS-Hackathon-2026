# RailPulse Documentation

Start with the root `README.md` for a one-page overview. This folder goes
deeper into each part of the project:

- **FEATURES.md** — every feature in the system, what it does, and why it
  was built that way.
- **ARCHITECTURE.md** — how the pieces fit together: data flow from
  simulator → features → model → API → dashboard.
- **API.md** — every HTTP endpoint, its auth requirement, request/response
  shape, and an example call.
- **TECH_STACK.md** — every technology used and what it's used for.
- **SETUP.md** — step-by-step instructions to run the whole thing locally,
  including the historical model and the frontend.
- **LIMITATIONS.md** — an honest account of what's validated, what's
  demoable-but-unvalidated, and what's genuinely out of reach without
  institutional data access.
- **CHANGELOG.md** — how the project got to its current state, in order.

If you're a judge with five minutes: read `FEATURES.md` and
`LIMITATIONS.md`. If you're picking this up to run or extend it: read
`SETUP.md` then `ARCHITECTURE.md`.
